## 기존 결정과 달라진 점

9월 23일 명세는 Apps Script를 포함한 간접 Cloud 의존을 금지했으나, 사용자는 9월 27일 Apps Script로 확정한 보완안 반영을 요청했다. 더 최근의 구체적 요청을 적용해 **Cloud 콘솔·서비스계정 직접 설정 없이 Apps Script 사용**으로 구현했다. Apps Script의 Google 관리형 Cloud 프로젝트 의존은 문서·설정 화면에 표시한다.

수동 저장 경로도 유지한다. “시트가 백업이므로 별도 백업 불필요”는 데이터 손실 방지 요구와 맞지 않아 전체 백업 기능을 없애지 않았다. 읽기에도 POST 본문 인증을 사용해 쿼리 URL에 시크릿이 남지 않게 했다.

## 8개 실제 전략 검증

사용자가 제공한 31개 보유행과 8개 전략을 정규화한 뒤 합성 종가로 전 계좌 평가를 실행했다. 개인 계좌명·수량·현금은 공개 저장소에 포함하지 않았다. 모든 목표비중 합계는 전략별 100%였고 한국 종목코드는 6자리 문자열로 보존되며, 전 전략이 오류 없이 평가되었다.

- 낙폭 매수는 계좌 총자산의 지정 상한까지 매수하고 상한 이상이면 추가 매수하지 않는다.
- 낙폭 전환은 여러 주식 티커의 총 비중을 80%에서 85%로 바꾸며 묶음 내부 목표 비율을 유지한다.
- 연 1회 보유 전략은 `frequency: "manual"`로 두어 사용자가 해당 평가에서 선택할 때만 목표복원을 실행한다.
- `CASH` 티커는 입력 분류와 무관하게 현금으로 정규화한다. 금 계정의 CASH가 실제 금 보유를 뜻한다면 별도 자산 티커가 필요하다.

복수 자산을 **각각** SMA 하회 시 현금화하는 LAA 변형은 기존 `sma_filter_rebalance`의 `sma_tickers`로 표현한다. `A AND (B OR C)` 같은 우측 중첩식은 한 줄 선형 카드에 그대로 넣을 수 없다. 식을 변환할 때는 `mom_rank → __winner__`처럼 상태 참조가 있는 조건을 복제하면 의미가 달라질 수 있어 자동 전개하지 않는다. 독립 범위에 여러 조건 행동을 동시에 합성하는 일반 규칙도 아직 지원하지 않는다.

## 기존 앱 기능 격차표

이 앱은 월별 핵심 운영을 자체 수행하는 범위로 구현했다. 원본 SQLite 앱 전체 코드가 제공되지 않았으므로 완전한 대체·모든 기능 동등성을 주장하지 않는다.

## 운영 검증 경계

Yahoo는 개발 환경에서 요청 제한·시간 초과가 발생했고, 실제 사용자 Sheets의 Apps Script URL·시크릿과 Streamlit 관리 세션은 제공되지 않았다. 브라우저의 localhost 접근도 차단되어 스크린샷 검증을 완료하지 못했다. 이 항목들은 합성 종가 기반 전략 검증 및 자동 테스트 성공과 별도로 남긴다.
